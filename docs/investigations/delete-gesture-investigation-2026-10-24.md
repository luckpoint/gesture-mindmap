# サムダウンで削除確認が開かないケースの調査

2026年10月24日。調査対象コミット：`6551878`。以下の原因・再現結果・行番号は修正前の記録。調査後、パン開始待ちによる操作抑止を修正した（末尾の「修正結果」参照）。

## 確認できた原因（修正前）

サムダウンの前または保持途中に `fist`（グー）が1フレーム入ると、その後は正しい `thumbDown` を保持しても削除要求が発火しない。選択ノードの有無とは独立した、コントローラーの操作切り替えによる抑止だった。

1. `ui-prototype/gestures/controller.js:128`：片手のグーも即座に `updatePan()` へ渡す。パン開始の安定待ち中から `panLastAt` が設定される。
2. 同ファイル`:231`：次のサムダウンで `panLastAt !== null` を検出し、`commandHeld = true` にする。まだ削除要求を実行していなくても、再操作待ちになる。
3. 同ファイル`:234`：以後のサムダウンは `commandReset` で返り、600msの保持判定へ進まない。
4. 同ファイル`:222`：解除にはパー・人差し指・グー等の中立ポーズを100ms安定認識する必要がある。サムダウンを保持し続けたり、一度手を画面外へ出すだけでは解除しない。

パンから削除へ直結させないためのガード自体は既存仕様だが、実際にパンしていない1フレームの認識揺れにも適用される。現在の片手グーへのパン割り当てと組み合わさり、削除の操作を妨げる。

## 再現結果

既存 `tests/ui-prototype.test.cjs` のDOMアダプターを使い、実際のインラインUIスクリプトと `CameraSession.io.frame()` を実行した。カメラやブラウザの実機測定ではない。各入力は50ms間隔、座標は固定し、削除可能なノード `a` を選択した。

| 入力 | 結果 |
| --- | --- |
| サムダウン40フレーム（2秒） | 削除確認が開く |
| グー1フレーム → サムダウン40フレーム | 選択は `a`、ノードは存在、確認は開かず `commandReset` |
| 上記の後、人差し指3フレーム → サムダウン14フレーム | 同じノードの削除確認が開く |

コントローラー単体でも「パー → サムダウン6フレーム → グー1フレーム → サムダウン40フレーム」で発火しないことを確認した。グーの代わりに1フレームの未確定ポーズ（`pose: null`, `ratio: .8`）を挟んだ場合は、その後の保持で削除要求が出た。

UIの大きなポーズ表示は `ui-prototype/index.html:1789` で入力フレームから独立して作られる。このため、内部では削除が抑止されていても「👎 親指を下」と表示される。上の再現でも確認した。

## グー判定に入るきっかけ

`controller.js:443` の下向き条件は `abs(thumbX) < thumbY * .7` で、真下からの傾きは約35度未満に限られる。一方、横向き条件は横成分が縦成分を上回ることを要求する。両条件の間では、親指が伸びていても4指が曲がっていれば `fist` に落ちる（`:455`）。

既存の `downwardThumb()` 合成ランドマークを画面内で回転し、以下を確認した。

| 真下からの傾き | 判定 | 親指の伸展 |
| --- | --- | --- |
| 0 / 30 / 34度 | `thumbDown` | true |
| 35 / 40 / 44度 | `fist` | true |
| 46度 | `thumbRight` | true |

ほかに、親指のMCP/IP曲げ角度が40度を超える、4指の屈曲条件を満たさない、2手として検出される、保持中の手のひら移動が正規化座標で0.04を超える等でも削除要求は抑止・再計時される。ただし今回の利用時にどれが起きたかは、実カメラのフレーム記録がないため未確定。

## 調査時の対応案

- 第一候補：パン開始待ちと、安定認識後のパン操作を区別し、1フレームのグーだけで削除の再操作待ちへ入らないようにする。実際のパン操作からの誤削除抑止は維持する。
- 親指が伸びた斜め下のポーズをグーへ落とす条件も見直す。下向きの範囲を広げる場合は、確認画面の左右入力との境界を検証する。
- ポーズ表示に加え、削除を受け付けない理由（再操作待ち・他入力中・対象なし等）が分かる表示を検討する。
- 回帰テストには「有効な選択あり、グー1フレーム、連続サムダウン」と「保持途中のグー1フレーム」を追加する。

暫定回避は、パーまたは人差し指を100ms以上認識させてから、サムダウンを真下に向けて600ms保持すること。

## 修正結果

`HandController` にパン開始済みを表す `panActive` を追加した。グーを `stable`（既定100ms）以上安定認識してパン操作へ入った時点で有効にし、`cancel()` で解除する。追加・削除コマンドの再操作待ちは、パンの入力時刻があるだけでは設定せず、`panActive` が有効な場合に設定する。

- サムダウンの前または保持途中に、パン開始待ちのグーが1〜2フレーム混ざっても、その後のサムダウンを600ms保持すると削除要求が出る。保持時間はグーの後から計り直す。
- 安定認識後のパンは、実際に移動していなくても、従来どおり中立ポーズを経由しなければ追加・削除へ移れない。
- コマンド発火後にグーが1フレーム混ざっても再発火しない。手を画面外へ出すだけでも再操作待ちは解除しない。
- 共通のガードを使うピースによる追加も同じ条件で検証した。

コントローラーの回帰テスト12件と、実際のUIスクリプト・`CameraSession.io.frame()` を通して選択ノードの削除確認が開く回帰テスト2件を追加した。

`node --test tests/hand-gestures.test.cjs tests/ui-prototype.test.cjs`：241件通過。`npm test`：全345件通過。実カメラでの確認は未実施。斜め下の親指をグーと判定する条件と、操作抑止理由の表示は今回の修正には含めず、引き続き検討事項とする。

## 2026年10月25日：静止したグーからの削除を修正

サムダウンの認識は改善したものの、削除を受け付けない場合があるとの追加報告を受領。残っていた経路として、グーを100ms以上認識すると、画面を動かしていなくても `panActive` が有効になり、その後のサムダウンを保持しても `commandReset` から進まないことを合成入力で再現した。50ms間隔の静止グー8フレームをサムダウンの前／保持途中に挟むと、UIの削除確認も開かなかった。実際の利用時にこの経路だったかは未確定。

パン開始済みのフラグを、実際に `io.pan()` を呼んだことを示す `panMoved` に置換。安定待ち後でも、静止や不感帯内の揺れだけなら削除・追加コマンドへ移れる。グーの後は600msの保持を最初から計り直す。実際にパンした後の中立ポーズ要求、同じポーズの連続発火抑止、削除確認と確定の分離は維持する。

回帰テストでは、サムダウン／ピースの前と途中の静止グー、不感帯内の揺れ、静止グーによる再操作、移動したパン後の抑止、およびUIの削除確認を検証する。配信更新番号は `20261025-delete-pan-2`。実カメラでの再確認は未実施。
