## 1. 前提と完成の定義

現在の作業フォルダには設計書だけがあり、アプリのコード・開発設定はない。新規のWebアプリとして構築する。本書は実装順序と検証方法を定める計画であり、実機互換性や性能を確認済みという意味ではない。

2026年10月22日の方針更新：日本語入力・OS標準音声入力は別途実績があるため、利用できる前提で実装を進める。段階A1の独立した事前検証は一旦スキップし、開発の前提条件にしない。アプリへの組み込み後に行うIME・ショートカット・編集UIの統合確認は残す。

完成は、Macで「親を選ぶ → 子の編集欄を開く → OS標準音声入力で日本語を入れる → 修正・確定 → カメラのピンチで動かす → 次の枝を足す」が繰り返せること。加えて、iPadのタッチ・日本語編集・OS標準音声入力を確認し、Undo/Redo、保存、JSON入出力で作業を回復できることとする。iPadのカメラ操作は検証結果を別途記録する。

設計書の採用方針を維持する。

- Vite、TypeScript、React、Zustand、HTMLノード＋SVGの枝、Pointer Events。
- IndexedDB＋Dexieによる一つのローカルマップの自動保存。
- MediaPipe Tasks Vision。専用Workerを基本に技術検証する。
- 通常のHTML編集欄・チャット欄でOS標準音声入力を利用。アプリからマイク権限を要求しない。
- チャット欄の指示は、ルール解釈で済まないものだけLLM中継へ送る（設計書6.5節）。
- HTTPSの静的配布。配布先は実機検証時に決める。

ログイン、同期、指示の解釈以外のAI機能、アプリ内音声認識、相互リンク、全体の自動再配置、独自Rust/WASMは今回のタスクに含めない。依存のバージョンと公式APIは実装開始時に確認し、lockfileで固定する。

## 2. 実装を進める順序

```text
P0 開発基盤
  ↓
A2 カメラ・推論・Workerの実機検証（A1は実績を前提にスキップ）
  ↓
B1 データ・コマンド・履歴
  ↓
B2 描画・座標・通常操作
  ↓
B3 編集・キーボード・つなぎ替え
  ↓
B4 保存・JSON入出力
  ↓
C1 ジェスチャー統合 → C2 声と手の連続操作 → C3 チャット欄・LLM解釈
  ↓
D1 性能測定・実機調整 → D2 親子で評価・配布準備
```

A1の検証画面や再検証は作業に含めず、標準HTML編集欄へ直接実装する。A2の検証コードを本体へ直接拡張せず、Bの共通コマンドへ接続する。カメラの不成立は通常操作の開発を止める理由にしないが、手の操作を未実装のまま完成とは判定しない。

各タスクは下表の完了条件を満たしてから次へ進む。ただしA2は、動作不成立でも原因・代替構成の評価・保留範囲を記録すれば調査完了としてBへ進める。この場合もMacの手操作は未達のままであり、全体の完成条件は満たさない。日数は現時点では確約せず、段階Aで対象端末と技術的な制約が分かった時点で見積もる。

## 3. 構成と責務

想定する配置。実装の規模に合わせてファイルを分割する。

```text
src/
  app/                    画面構成、初期化、エラー表示
  domain/
    model.ts              マップ型と不変条件
    commands.ts           確定操作と検証
    history.ts            Undo/Redo
    tree.ts               子孫探索、循環検証
  store/                  Zustand、選択・編集・操作状態
  features/
    map/                  HTMLノード、SVG枝、仮配置、座標変換
    input/                Pointer Events、キー操作、テキスト編集
    gestures/             カメラ、Worker通信、ピンチ状態機械
    persistence/          Dexie、保存キュー、JSON検証
  components/             ツールバー、編集操作、状態表示
  diagnostics/            段階Aの検証画面、性能表示、負荷データ
public/mediapipe/          採用するモデル・WASM等の配布資産
tests/                    領域ロジック・統合・ブラウザテスト
docs/                     端末検証、測定結果、設計変更の記録
```

入力アダプター → 一時状態の更新／共通コマンド → 確定データ → 描画・保存、の向きを守る。MediaPipeからマップやIndexedDBを直接変更しない。

### 状態の分離

| 状態 | 内容 | 履歴・保存 |
|---|---|---|
| マップ | 形式バージョン、マップID・名前、中心ID、ノードID・文字列・親・順序・世界座標 | 確定操作として履歴化・保存 |
| 表示設定 | パン・ズーム等、復元対象に選んだ設定 | 内容のUndoから独立して保存 |
| 編集 | 対象ID、新規／既存、下書き、IME変換状態 | 一時状態。確定時のみマップへ反映 |
| 操作 | 選択、ホバー、ドラッグ開始座標・仮変位、つなぎ替え候補 | 一時状態 |
| カメラ | 接続状態、最新推論、カーソル、追跡・ピンチ状態 | 一時状態。映像やランドマークは保存しない |

中心は一つ、中心以外の親は必須、全ノードが中心から到達可能、循環なし、座標は有限値、IDは一意という不変条件を持つ。削除・つなぎ替え・読み込みでも維持する。

## 4. 実装上の判断案

以下は設計書にない細部を埋める初期案。実装時に変更する場合は理由を記録する。

| 論点 | 初期案 |
|---|---|
| 中心の削除・兄弟追加 | 中心の削除は無効。中心でEnterを押した場合は子を追加する |
| 親ノードの削除 | 配下を含めて削除し、件数を操作名に示す。一回のUndoで全体を復元する |
| 新規追加の取消 | ノードは仮表示し、文字列の初回確定で追加を履歴化。空欄・Escでは仮表示を除去する |
| 既存ノードの編集 | 確定操作で更新。空欄では確定せず案内し、Escでは元の内容に戻す |
| 編集の確定 | 画面上の「確定」を常設。Enterは変換中でない場合のみ編集を確定し、マップ操作へ伝播させない |
| 編集中のTab・フォーカス離脱 | IME変換中でないTabは現在の編集を確定し、そのノードの子を追加して編集する。フォーカス離脱でも現在の編集を確定する。新規の空欄は取り消す |
| Escとフォーカス | 編集・ドラッグ・つなぎ替え中はその操作を取消。通常時はツールバーへフォーカスを移し、Tabで離脱できるようにする |
| 操作の競合 | 編集・ドラッグ・つなぎ替えは排他的。カメラ推論が動作中でも、編集欄や通常入力の操作を優先する |
| 移動 | 対象と全子孫に同じ変位を適用。中心なら全ノードを平行移動。パンはビューだけを変更する |
| 履歴 | 初期は確定マップのスナップショット方式。件数上限を設け、100／500ノードでメモリを測定する |
| キー移動の履歴 | Alt＋矢印の連続押下はキー解放までを一操作にまとめる |
| Undo中の未確定操作 | 先に下書き・移動プレビューを取消し、確定済み履歴とは区別する |
| JSON読み込み | 全体検証・保存を終えてから置換する。取消や失敗では現在のマップを維持し、成功時は選択・履歴を初期化する |
| 複数タブ | 同一マップの同時編集は対象外。二つ目のタブでは編集を止める仕組みを用意し、上書き競合を避ける |

文字編集のUndoは入力欄に委ね、キャンバス上のUndoと分離する。Redoは新しい確定操作で破棄する。無変更の確定や取消は履歴を増やさない。

2026年10月22日のUIレビュー後の決定：実際の使いやすさを優先し、編集中のTabによる「確定して子を追加」とフォーカス離脱時の確定を採用する。「声で追加」のUIモックは、チャット欄＋OS標準音声入力へ置き換えた（同日、設計書v0.3）。

## 5. タスクと完了条件

### P0：開発基盤

**作業**

- Vite＋React＋TypeScriptの最小アプリと依存パッケージを用意する。
- 型チェック、lint、production build、Vitest、Playwrightの実行入口を整える。
- 通常画面と技術検証画面を分け、端末・ブラウザ版を記録する書式をつくる。
- iPadから到達可能なHTTPS検証URLを用意する。配布先の選定・設定はこの段階の実装タスクとする。

**完了条件**：Macで起動・ビルドでき、iPadで同じ検証画面を開ける。依存の固定と実行手順が記録されている。

### A1：日本語編集・OS標準音声入力（事前検証を一旦スキップ）

**前提**：ユーザーから別途実績があると確認済み。標準HTML入力欄で日本語入力・OS標準音声入力を利用できるものとして進め、独立した検証画面の作成や利用可否の再検証は行わない。B以降への着手条件にはしない。

**本体実装で扱う事項**

- B3で標準HTML入力欄、確定・取消、IME変換中のキー処理を実装する。
- C2で入力・修正・確定とマップ操作の連携を確認する。
- iPadのキーボード表示中も編集欄と確定操作を見えるようにする。必要に応じてVisual Viewportを用いる。
- OS音声入力にアプリ固有の開始ボタンや認識セッションを設けない。

### A2：カメラ・推論・Worker

2026年10月22日 実装進捗：静的UIプロトタイプにカメラ入力、専用Worker、相対移動・ピンチ状態機械、移動／Undoとの接続、5fps比較構成を追加した。資産取得とMac／iPad実機検証は未完了。実装範囲・起動手順・検証状況は[ジェスチャー検証記録](../guides/gesture-validation.md)を参照。A2の完了条件は未達として扱う。

2026年10月23日 ユーザー確認：実際に試せた旨の報告あり。ピンチ時にノードがずれる問題と、ポインタが震えて選択しにくい問題が未解決。原因調査は別担当が行う方針とし、[対応状況と課題の引き継ぎメモ](../investigations/gesture-handoff-2026-10-23.md)を作成した。端末別の詳細検証とA2の完了判定は引き続き未了。

**作業**

- 明示的な開始・停止、カメラ権限拒否、利用不可の表示を用意する。
- 設計書7節に従い、初回の開指検出でポインタをマップ表示領域の中央に置き、人差し指先の相対移動で鏡像方向へ動かす。仮ノード一つをピンチでつかみ、動かし、開いて放す。
- 専用Workerでの推論初期化・フレーム転送・終了を、対象Safariを含めて確認する。
- 処理中のフレームは一つに制限し、待ちフレームを蓄積しない。転送した画像資源を必ず解放する。
- モデル・WASMの同一配布元からのロード、失敗・再試行、Worker停止後の資源解放を確認する。
- 推論時間とカーソル表示までの時間を分けて測定する。

**完了条件**：Macでカーソルと仮ノードの操作が動く。iPadの成立／不成立が記録されている。Workerが不成立なら低頻度のメインスレッド推論を比較し、通常操作を阻害する場合は当該端末の手操作を保留する。

### B1：データ・コマンド・Undo/Redo

**作業**

- データ型、不変条件、初期マップ、ID生成を実装する。
- `addChild`、`addSibling`、`editText`、`moveSubtree`、`reparent`、`deleteSubtree`、マップ名変更を共通処理にする。
- 操作前後を一履歴にまとめ、Undo/RedoをUIから独立して実行できるようにする。
- 循環、自分自身・子孫への接続、中心のつなぎ替え、存在しないIDを拒否する。

**完了条件**：枝移動・つなぎ替え・配下削除がそれぞれ一回のUndoで復元でき、不正な操作でマップが変わらない。

### B2：描画・座標・マウス／タッチ

**作業**

- HTMLノードとSVG枝を共通の世界座標に置く。入力座標から世界座標への変換を一箇所に集約する。
- 親付近の空き方向に新規ノードを仮配置し、既存ノードは動かさない。
- 選択・ホバー・移動中を枠と文言でも区別する。
- Pointer Capture、移動開始しきい値、`pointercancel`を扱う。ノードの一指ドラッグと背景のパン、二指のパン／ズームを区別する。
- マウスのホイール操作、ズーム、全体表示、ノード実寸を考慮した表示範囲計算を実装する。
- ドラッグ中は仮変位だけを更新し、解放時に共通コマンドを一回発行する。

**完了条件**：拡大縮小・パン後も狙ったノードを扱える。枝が追従し、位置移動だけでは親が変わらない。取消や入力中断で元へ戻る。

### B3：編集・キーボード・つなぎ替え

**作業**

- 標準HTML編集欄をノードへ実装し、追加から初回確定までを一操作にする。日本語入力・OS標準音声入力の利用可否は事前検証済みの前提とする。
- Tab、Enter、F2、矢印、Alt＋矢印、Delete／Backspace、Undo/Redo、Escをキャンバス内で扱う。
- 通常の矢印キー選択は、[設計書5.1.1節「矢印キーで兄弟を順にたどる」](../design/mind-map-prototype-design.md#511-矢印キーで親子と兄弟を移動する)に従う（2026年10月24日合意）。ユーザー指定により右側の合意済みサンプルのみ実装反映済み。親の↑/↓で子の先頭・末尾へ入り、子の←/→で兄弟を見た目の順序でたどり、先頭・末尾では停止する。親や別の枝への近傍探索へ切り替えない。
- 右向きの枝ではShift＋←で親へ戻る。左・上・下の枝でのキー対応、中心や下位階層への移動、順序算出方法の他方向への拡張は、同節の未確定事項を具体化してから実装する。
- つなぎ替えモード、候補と線のプレビュー、確定・取消を実装する。マウス・タッチ・キーから同じ処理を使う。
- 入力欄、IME変換中、ツールバーではキャンバスのキー処理を抑止する。
- ボタン名、フォーカス表示、状態の読み上げ、タッチ対象の押しやすさを整える。

**完了条件**：マウス・タッチ・キーボードを切り替えて同じマップを編集できる。日本語変換のEnterで兄弟が増えず、編集中のBackspaceでノードを削除しない。キーボードだけでキャンバスから離脱できる。今回の矢印キーの変更については、設計書5.1.1節の右側サンプルの受入確認を満たし、順序の算出仕様と検証結果を残す。右向きの枝の各子からShift＋←で親へ戻れる。他方向の具体化は後続対応とする。

**今回の検証結果**：右側サンプルの受入確認を自動テストに反映し、`npm test` 全248件成功。実ブラウザ確認はChromeの起動異常（`SIGABRT`）により未完了。詳細は設計書5.1.1節の実装状況を参照。

### B4：自動保存・JSON入出力

**作業**

- Dexieのスキーマと保存形式を用意し、起動時に最後の保存済みマップを復元する。
- 確定操作から保存を予約し、連続操作をまとめる。書き込みは順序を保ち、古い保存が新しい状態を上書きしないようにする。
- 保存中・保存済み・保存失敗を表示する。失敗してもメモリ上の編集とJSON書き出しを維持し、再試行できるようにする。
- JSONの形式バージョン、型、ID、親、到達性、循環、順序、有限座標を読み込み前に検証する。未知の新しい形式は拒否する。
- 読み込みは検証済みデータの保存成功後に画面へ反映する。既存マップの置換を明示し、未確定の編集がある間は実行させない。
- 多重タブの編集競合を防ぎ、DB利用不可・破損時は勝手に上書きせず、復旧案内を表示する。

**完了条件**：再読み込みとJSON往復で文字・関係・位置を保持する。不正JSON、書き込み失敗、保存順序の競合で作業中データを壊さない。初回はv1のみ対応し、将来の移行処理の入口を設ける。

### C1：ジェスチャーを通常操作へ統合

**作業**

- A2の推論を入力アダプターにし、B2と同じヒットテスト・移動プレビュー・確定処理を使う。
- `Waiting`、`Ready`、`Hover`、`Dragging`、`Suspended`を実装し、ピンチ開始時に対象を固定する。
- 手の大きさで正規化した距離、開閉で異なる閾値、安定判定、平滑化、鏡像・映像切り抜き・ビュー変換を扱う。人差し指先の相対移動と感度調整を使い、端を越えた入力は蓄積しない。
- ピンチ開始・開指時に基準を取り直し、つかむ前のノードとの位置関係を保持する。解放後はその位置からポインタを自由に動かし、中央へ戻さない。
- 追跡消失で停止し、初期300msの猶予内に同じ手でピンチ継続と判断できた場合のみ再開する。判定不能・猶予超過・再検出時の開指は取消す。
- 復帰時はオフセットを取り直し、取消後の次の操作には開指を要求する。同じセッションの再検出では最後のポインタ位置を維持する。空白ピンチや閉じたままの対象への進入で操作を開始しない。
- つなぎ替えモードではピンチを候補選択として扱い、通常移動と区別する。
- 停止、画面離脱、バックグラウンド化で仮操作を取消し、MediaStreamの全トラック・推論・Workerを終了する。自動再開しない。
- カーソル・対象枠・追跡消失案内・非表示にできるプレビューを用意する。

**完了条件**：Macで意図した対象を動かし、一回のUndoで戻せる。追跡消失・再検出・カメラ停止で飛びや勝手な確定が起こらない。カメラ拒否・推論失敗でも通常編集が続く。

### C2：声と手の連続操作

**作業**

- 設計書3.1のMacシナリオと3.2のiPadシナリオを通して実施する。
- 編集中はジェスチャーによる構造変更・移動を抑止し、確定したノードを続けて手で操作できるようにする。
- 初回の短い使い方案内、保存状態、カメラ状態を日本語で整える。

**完了条件**：Macで音声入力から手の移動、次の追加へ繰り返し進める。iPadではキーボード表示で編集欄や確定操作が隠れず、タッチと音声で継続できる。カメラやマイクなしでも通常入力が成立する。

### C3：チャット欄・LLM解釈

**作業**

- サイドバー（広い画面）／下からのシート（狭い画面）のチャット欄、開閉状態の保存、選択中ノードの表示を実装する。
- 指示の形でない文はすぐ子として追加し、決まった言い方はルールで解釈する。複数候補の聞き返し、削除の確認、拒否理由の表示を扱う。
- 解釈結果はB1の共通コマンドで実行し、一回のUndoで戻す。履歴の「元に戻す」は最新の操作にだけ出す。
- LLM中継（Cloudflare Workers等）を用意し、マップの木構造と選択中ノードを渡してtool useで操作だけを返させる。通信失敗・遅延時もルール解釈と通常操作を止めない。
- 外部送信の旨をチャット欄に表示する。

**完了条件**：Mac・iPadで、OS標準音声入力でチャット欄に話した指示から追加・書きかえ・つなぎ替え・削除ができ、Undoで戻せる。iPad縦向きでキーボード表示中もシートの入力欄が見える。LLMなしでも指示の形でない文とルール解釈が動く。

### D1：性能・互換性の確認

**作業**

- 100ノードの代表マップと500ノードの負荷マップを用意する。
- カメラ無効／有効で追加・編集・枝移動・パン／ズームを測定する。
- 高頻度の更新を局所化し、Zustandの購読範囲、React再描画、SVG枝の更新対象を調整する。
- 長い停止や遅延が残る場合だけ、描画範囲制限や空間探索を検討する。Rust/WASMやCanvas等は計測根拠を残して再判断する。

**完了条件**：通常操作の50ms目安・60fps目標、手の15〜30推論/秒・150ms以内目標を、端末ごとの測定結果と照合できる。平均・p95・停止を記録し、未達を明記する。実際の手から表示までの遅延は動画等で観察し、推論時間と混同しない。

### D2：親子で評価・配布準備

**作業**

- 5〜10分の自由なテーマで、通常入力、音声併用、手の操作併用を比較する。
- 思考が止まる場面、誤操作、修正、つなぎ替えの理解、楽しさ、腕の疲れを記録して優先度順に修正する。
- Macで同条件10回中8回以上のピンチ移動を初期目安にし、大人・子どもや距離の条件も記録する。
- iPadのジェスチャーも試し、タッチとの差と未対応の理由を記録する。
- パッケージ・モデル・WASMのライセンス、静的配布時の資産ロード、カメラ映像を送信・保存していないことを確認する。
- 起動・ビルド・書き出し・読み込みの手順、対応端末、制約をREADMEにまとめる。

**完了条件**：仕様の受け入れシナリオと評価目標について、達成／未達／未検証と証拠が残る。見た目や自動テスト成功だけで完成とはしない。

## 6. 検証の分担

自動テストはデータ破損や複数入力に共通する規則を中心にする。OS音声入力とカメラの体感品質は実機で確認する。

| 対象 | 方法 | 重点 |
|---|---|---|
| ツリー・コマンド | Vitest | 循環拒否、配下移動・削除、中心の制約、不正操作で不変 |
| 編集・履歴 | 単体／統合 | 新規追加＋初回編集の一履歴、空欄・Esc、Undo/Redo、未確定状態の取消 |
| 座標 | Vitest | 世界／画面座標の往復、ズーム・パン・鏡像・映像切り抜き後の選択 |
| ピンチ状態機械 | 記録／合成ランドマーク＋仮想時刻 | 閾値付近の揺れ、追跡消失、同一手判定、猶予、復帰オフセット、開指待ち |
| 永続化 | IndexedDB統合 | 保存順序、失敗・再試行、復元、JSON往復、不正・未知バージョンの拒否 |
| ブラウザ操作 | Playwright | 追加・編集・移動・つなぎ替え・Undo・JSON・フォーカス離脱の主要経路 |
| 日本語・OS音声・タッチ | Mac／iPad実機 | IME、OS音声入力、ソフトウェアキーボード、ブラウザ競合、タッチ取消 |
| カメラ・性能・体験 | Mac／iPad実機 | 権限拒否、追跡消失、背景移行、遅延、成功率、疲れ |

PlaywrightのWebKitテストをiPad Safari実機評価の代替としない。自動テストのIMEイベント合成だけで日本語・音声入力が確認できたとは扱わない。

## 7. 主なリスクと対処

| リスク | 先に確かめること | 不成立時の扱い |
|---|---|---|
| Safari上のWorker・映像転送 | A2で実際のモデルと資産をロード | 低頻度構成を測定し、当該端末の手操作の制約を記録 |
| iPadの入力欄が隠れる | B3でキーボードを考慮して編集UIを実装し、C2で統合確認 | 編集欄の表示位置を調整 |
| 手が震える・追跡が切れる | A2／C1で距離・照明・手の大きさを変える | 閾値・平滑化・操作範囲を調整。取消の安全性を維持 |
| 操作をまたいでUndoが壊れる | B1から共通コマンドと操作単位を固定 | デバイス別の履歴処理を作らず、共通層を修正 |
| 保存失敗・古い保存の上書き | B4で失敗と遅延を注入 | メモリ上の内容と書き出しを維持し、保存キューを修正 |
| 推論で描画が止まる | A2とD1で推論有効／無効を比較 | Worker・頻度・更新範囲の順に調整 |
