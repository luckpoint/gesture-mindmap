# ハンドトラッキングの検知候補

2026年10月23日更新。実装済みの操作と、追加・削除への割り当て案をまとめる。追加・削除のジェスチャーと確認ダイアログは実装済み。検知候補は実カメラでの精度を保証するものではない。

## 現在の構成

MediaPipe Hand Landmarkerで最大2手を認識する。各手の21点のランドマークと左右の手の推定を取得できる。現在は画像内の2D座標を使用しており、奥行きやworldLandmarksを操作には使っていない。

- 片手：手のひら中心の8方向移動でアクティブノードを切り替える。親指と人差し指のピンチでつかみ、手の移動でノードと子孫を動かし、指を開いて確定する。
- 両手：手のひら中心間の距離が増えるとズームアウト、減るとズームインする。
- グーはニュートラル。人差し指だけを300ms以上立てると一時停止・再開をトグルする。別の形を100ms以上認識してから次のトグルを受け付ける。
- 一時停止・人差し指・グーを両手ズームより優先する。それ以外の両手検出では片手操作よりズームを優先する。

## 片手の候補

| 検知対象 | 判定に使う情報 | 現状・検討事項 |
| --- | --- | --- |
| 上下左右・斜めへの移動 | 手のひら中心の変位 | 8方向選択・ピンチ移動で使用中 |
| 移動速度・スワイプ | 変位と経過時間 | 未実装。ゆっくりした移動と素早い払いを区別する |
| 静止・保持時間 | 座標や形が一定範囲内にある時間 | 未実装。微小な揺れの許容が必要。既存操作の開始時には安定待ちを使用 |
| グー／パー・開き具合 | 各指の関節角度や指先の位置 | グーのニュートラルは実装済み。手の向きによる影響を確認する |
| 人差し指のみ・ピース・親指を立てる | 指ごとの曲げ伸ばし | 人差し指のみの一時停止トグルは実装済み。ピース・親指は未実装 |
| 親指＋人差し指のピンチ | 指先間距離／手の大きさ | 実装済み。閉じる／開くで異なる閾値を使用 |
| 親指＋中指など別のピンチ | 対象となる指先間の距離 | 未実装。指の重なりと既存ピンチとの区別を確認する |
| 短いピンチ・長押し・連続ピンチ | ピンチの継続時間・回数 | 未実装。現在のつかみ操作との競合や単発の判定待ちが生じる |
| 画面内での手の傾き・回転 | 手首と指の付け根の方向 | 未実装。基準角と回転の連続性を扱う |
| 手のひら／甲・横向き | ランドマークから推定する手の面の向き | 未実装。3D情報の活用候補。真横では指が重なりやすい |
| カメラへ近づける／遠ざける | 見かけの手の大きさなどの時間変化 | 未実装。傾き・指の形との混同があり、カメラからの絶対距離とは扱わない |
| 円・往復などの軌跡 | 手の位置の時系列 | 未実装。開始／終了と通常移動の区別が必要 |
| 左手／右手の区別 | handednessの推定 | 片手の追跡リセット判定で使用中。人物識別や永続的な手のIDではない |

| --- | --- | --- |
| 両手を広げる／近づける | 手のひら中心間の2D距離の変化 | ズームとして実装済み。左右・斜め・上下の間隔変化を扱う |
| 両手を同じ方向に動かす | 両手の中点の変位、距離の維持 | 未実装。ズームとの同時操作や優先順位を検討する |

| 両手の形の組み合わせ | パー＋グーなど各手の形 | 未実装。組み合わせ数より誤認識の少なさを優先して検討する |

## 両手ズームの実装仕様

- 各手の中心は手首と4本の指の付け根（ランドマーク0、5、9、13、17）の平均。指先を使わず、指の曲げ伸ばしの影響を抑える。
- 距離は画像幅を1とする単位で計算し、縦方向は画像の縦横比を補正する。検出結果の手の並び順には依存しない。
- 両手を100ms継続して認識してから開始する。その間は距離の基準を更新する。
- 基準からの距離変化が0.008未満なら反映しない。反映時の倍率は `exp(-距離変化 × 2.5)`。広げるほど縮小、近づけるほど拡大する。
- ズーム中心は表示中のキャンバス中央。既存の25〜200%の倍率制限と表示範囲制限を適用する。
- ノード移動中に両手へ切り替わると、未確定のノード移動を取り消してからズームする。ズームはノード編集履歴に追加しない。
- 片手に戻ったときは基準を破棄し、安定した開指から片手操作を再開する。残った手の位置で即座にノードを切り替えたりつかんだりしない。
- 両手中心間距離が0.05未満、不正座標、追跡消失では停止する。1秒超の認識間隔、時刻の逆行、距離の0.2超の急変では基準を取り直す。
- 編集・つなぎ替え・通常のポインタ入力などの最中は既存の入力抑止を適用する。

## 今後の検証・検討

ランドマークから判定できることと、意図して使いやすいことは別に評価する。現在の両手ズームの自動検証結果と実機手順は[検証記録](gesture-validation.md)を参照。

新しいジェスチャーを試す際は、操作に割り当てる前に検知状態・継続時間・変位を表示して確認するとよい。特に手の交差、片手の一時的な未検出、カメラとの距離変化、低い認識頻度での切り替えを確認する。

定型ポーズについては別機能のGesture Recognizerも選択肢となる。現時点では導入していない。

参考：[Hand Landmarker公式仕様](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/web_js)、[Gesture Recognizer公式説明](https://developers.google.com/edge/mediapipe/solutions/vision/gesture_recognizer)。


## 追加・削除の割り当て案

### 推奨する組み合わせ

既存の方向選択・ピンチ移動・グー・人差し指・両手ズームを維持し、新しいポーズはまず2つに絞る。以下は本アプリ向けの仮説であり、一般に通用する標準ジェスチャーとは扱わない。

| 操作 | 第一候補 | 意味の手がかり | 発火した結果 |
| --- | --- | --- | --- |
| 子を追加 | ピース（人差し指＋中指を立てる）を約600ms保持 | 指が二股に分かれる＝枝を増やす | 選択ノードの子を1つ作り、文字編集へ入る |
| 削除を要求 | 親指だけを下に向けて約600ms保持 | 下げる＝取り除く | 選択ノードを対象とする確認ダイアログを開く |
| 削除範囲を選ぶ | ダイアログ内で選択 | 削除結果を文章とプレビューで示す | 範囲の選択だけで、まだ削除しない |
| 削除を確定 | 明示された削除ボタンを押す | 通常の確認操作 | 選んだ範囲を削除し、Undoを提供する |

600msは試作時の初期値。認識頻度・疲れ・誤発火を見て調整する。映像の横に手の形、操作名、保持の進捗を表示し、ポーズの意味を画面から確認できるようにする。

追加は選択中のノードが親。未選択なら中心を親にする。兄弟追加は既存のEnter／メニューを残し、必要性が分かるまでは別ポーズを増やさない。新規ノードは通常の文字入力・OS音声入力で編集し、空欄のまま閉じたら取り消す。追加から最初の編集確定までを1回のUndoにまとめる。

### 比較した候補と採否

| 候補 | 良い点 | 既存操作との関係・難点 | 判断 |
| --- | --- | --- | --- |
| ピースで追加 | 片手ででき、枝分かれの形に結びつけられる | 人差し指だけの一時停止との切り替え途中が重なる | 第一候補。切り替え途中での誤発火を検証する |
| 親指を上げて追加／下げて削除 | 増やす／減らすの対で覚えやすい | 親指が横を向く場合や、残りの指がグーに見える場合の区別が必要 | 対案。ピースとの比較対象にする |
| ピンチして引き出して追加 | 枝を引き出す比喩が分かりやすい | 現在のノード移動と同じ動作になる | 見送る |
| ピースを閉じる「はさみ」で削除 | 切る動作とのつながりが強い | 追加のピースと競合し、閉じる途中が人差し指にも見える | 見送る |
| 素早く払って削除 | 捨てる動きに近い | 方向選択やドラッグの速い動きと競合する | 見送る |
| 両手で×を作って削除 | 取消・削除を連想しやすい | 手の重なり、ズームとの競合、両腕の負担がある | 見送る |

親指を下げるポーズがグーと区別しにくければ、閾値を緩めて採用せず割り当てを再検討する。確認がある場合も、意図しないダイアログが頻繁に開けば操作を妨げる。

### 削除確認ダイアログ

削除は必ず確認ダイアログを開く。ジェスチャー、メニュー、Delete／Backspace、チャットのどの入口でも同じ確認と削除処理を使う。現状、メニュー／キーの削除は即時に子孫ごと削除し、チャットだけが独自の確認を持つため、実装時には共通化が必要。

例：親Pの下にAがあり、Aの子がB・C、Bの子がDの場合。

| 選択肢 | 削除されるもの | 残る構造 |
| --- | --- | --- |
| このノードだけ削除し、子を親につなぎ直す | Aだけ | P → B → D、P → C |
| 子孫もまとめて削除 | A・B・C・D | Pを残し、A以下の枝を取り除く |

「詰める」の推奨定義は、**親子構造を1段詰めること**。Aの直接の子をAの親へ付け替え、孫以下のつながりは保つ。昇格した子は元のAの兄弟順の位置へB・Cの順で入り、それ以外の兄弟順は維持する。自由配置のマップなので、座標は保持する。自動で隙間を埋める再配置は別機能とし、この削除には含めない。

ダイアログには次を表示する。

- タイトル：『「A」を削除しますか？』。対象名はテキストとして表示する。
- 範囲：上記2択。各選択肢に削除数と残る子の扱いを表示する。
- プレビュー：消えるノードと付け替わる枝をマップ上に表示する。選択時点では保存データ・履歴を変更しない。
- ボタン：『キャンセル』と、範囲に応じた『この1個を削除』『子孫を含む4個を削除』。

子があるときは範囲を未選択から始め、範囲を選ぶまで削除ボタンを無効にする。初期フォーカスはキャンセル。子がなければ範囲選択は省略し、1個の削除を確認する。中心ノードは削除できず、理由を表示する。

削除実行後は元の親を選択する。どちらの方式も削除・付け替え・兄弟順の変更を1回のUndoで元に戻せるようにする。確認を開いた時点の対象IDを固定し、確定前に対象や子孫が変わった場合は、内容を更新して確認をやり直す。

### 手だけでダイアログを操作する場合

最初の実装ではマウス・タッチ・キーボードで選択／確定できることを必須とする。手だけの確認は次の案を別途検証する。

1. 開いた手の上下移動で、範囲2択・キャンセル・削除ボタンのフォーカスを移す。マップのノード選択・ズーム・移動には伝えない。
2. フォーカスされた項目を、新しいピンチを約600ms保持して選択／実行する。範囲を選んだだけでは削除しない。
3. グーではフォーカスを保持して待機する。グーをキャンセルや削除確定には割り当てない。
4. 人差し指は引き続き手操作の一時停止・再開。ダイアログは閉じず、一時停止中はピンチでも確定しない。

ダイアログを開いた親指のポーズ、その途中の形、すでに閉じたピンチを確定入力に流用しない。開いた手を安定認識してから新しい入力を受け付ける。削除用の親指ポーズを保持しても確認・実行を繰り返さない。Esc・キャンセル・閉じる操作では変更しない。

### 競合を避ける条件

- 一時停止中は、追加・削除・方向選択・ピンチ移動・ズームをすべて抑止する。人差し指の再開操作だけを受け付ける。
- 編集中はジェスチャーによる追加・削除を受け付けない。文字の確定は通常入力に任せる。
- ドラッグ中に新しいポーズへ変わっても、追加・削除へ直結させない。移動プレビューを取り消し、グーまたは開いた手へ戻してから次のコマンドを受け付ける。
- 新しいポーズの候補を検知した段階で方向入力を止める。保持時間の途中で形が変わったら取り消し、その間の移動を方向選択へ繰り越さない。
- ピースと人差し指を判定する際は中指の状態も確認する。曖昧な中間姿勢ではどちらのタイマーも進めない。人差し指だけを300ms維持した場合は従来どおり一時停止になるため、ピースへゆっくり移る動作も実機で試す。
- 親指ポーズは、親指が伸びて下を向き、他の4本が曲がった状態としてグーより先に分類する。中間姿勢ではコマンドを発火させない。
- 追加・削除要求は片手時だけに限定する。両手への切り替えでは候補を取り消す。両手ズーム中にたまたま片方がピース／親指ポーズでも要求を出さない。
- 1回の保持につき1回だけ発火する。編集やダイアログを閉じても、別の形を安定認識するまでは再発火させない。
- 追跡消失・手の交代・大きな座標飛び・通常入力への切り替えでは保持判定を取り消す。復帰位置から追加・削除や方向選択を発火させない。

### 実機で決めること

第一候補のピース／親指下と、対案の親指上／親指下を比べる。説明前に意味が推測できるか、短い説明後に覚えて使えるか、左右の手や傾きで区別できるかを確認する。初期目安として各操作を10回試し、成功数・誤発火数・保持に要する時間を記録する。方向選択・ピンチ・一時停止・両手ズームの通常操作中に、新コマンドが誤発火しないかも測る。

削除確認では、孫を含む例を見せて2方式の結果を予測してもらう。子を残す選択で孫も残ること、座標は自動で詰まらないこと、キャンセルとUndoが分かることを確認する。

設計判断の参考：Appleはカスタムジェスチャーを簡潔に説明できることを重視している（[Gestures](https://developer.apple.com/design/human-interface-guidelines/gestures)）。NN/gはジェスチャーが記憶に依存するため、画面の手がかりで想起を助けることを勧めている（[Recognition and Recall](https://www.nngroup.com/articles/recognition-and-recall/)）。これらは設計原則の参考であり、上記の具体的な割り当ての有効性を示す実験結果ではない。


## 追加・削除の実装結果

`20261023-add-delete-7`として上記の第一候補を実装した。ピース／親指下を600ms保持して発火し、保持の進捗をカメラの案内に表示する。手のひらが基準から0.04以上動く場合は保持時間を取り直す。1回発火したらグーか開いた手を100ms安定認識するまで次の要求を受け付けない。

削除確認はネイティブのモーダルダイアログを使用し、メニュー・Delete／Backspace・チャット・ジェスチャーを共通処理へ接続した。子がある場合は範囲未選択から始める。選択に応じて削除数・残る構造の説明とマップ上の削除／つなぎ直しプレビューを表示する。子を残す場合は直接の子を元の親へ付け替え、兄弟順・孫以下・座標を保持する。1回のUndoで復元できる。

確認画面では開いた手の上下移動でフォーカスを動かし、新たなピンチを600ms保持して選択／決定する。開いた手を認識する前のピンチ、両手ズーム、追加・削除要求は確認画面では抑止する。人差し指の一時停止は維持する。

自動テストは122件通過。追加・空欄取消・Undo、削除方式、複数の子と孫の保持、兄弟順、プレビュー、キャンセル、対象固定、確認中の変更検知、手での確認操作、短いポーズや追跡の切れ目での誤発火抑止を確認した。Chromeによる画面検証は起動直後の異常終了で実行できなかった。実カメラでのポーズ認識精度と、デスクトップ／モバイルでの表示・フォーカスは実機確認が必要。
