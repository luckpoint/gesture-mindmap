# ハンドトラッキング改善メモ

2026年10月24日。ユーザー共有の21点ランドマーク図と現在の実装を照合して整理した改善候補。作成時点では以下は未実装。優先度「高」の実装状況は末尾に追記し、改善効果は実カメラで検証する。

## 確認した現状

- ランドマーク番号の取り違えはない。ピンチは親指先端 `4` と人差し指先端 `8`、手のひら中心は `0・5・9・13・17` の平均を使用している。
- 指の曲げ伸ばしは、MCP→PIPとDIP→TIPの方向、および手首からの距離で判定している。
- ピンチ比率は画像内の2D距離 `4 ↔ 8` を、手首から中指の付け根までの距離 `0 ↔ 9` で割っている。画像の縦横比は補正済み。
- ピンチの開閉には別々の閾値と安定待ちを使用し、移動には平滑化とデッドゾーンを適用している。
- 奥行きの `z` と `worldLandmarks` は操作判定に使用していない。

対象コード：[controller.js](../ui-prototype/gestures/controller.js) の `singleHandFrame` と `HandController`。

## 2026年10月24日：優先度「高」の実装

優先度「高」の3件を実装。更新番号 `20261024-hand-geometry-1`。この時点では中・低の項目は未着手。

- **関節角度**：PIP・DIPの曲げ角度（一直線を0度）を追加。伸展は両方40度以下、屈曲は少なくとも一方55度以上を、従来の方向・距離条件と併用する。関節が重なって角度を算出できない指は伸展・屈曲の確定対象にしない。world座標が有効ならその3D形状、それ以外は画像の3D／2D形状を使う。
- **ピンチの奥行き**：画像内のXY距離比と3D距離比の大きい方で開閉を判定する。3D距離比は有効なworld座標を優先し、なければ画像座標の `x × 幅・y × 高さ・z × 幅` を使用。world座標は分母・分子ともメートルで計算し、画像座標と直接混ぜない。画像のzが欠ける／不正な場合は手全体で2Dに戻す。world座標も欠損・不正・手のひら長ゼロならフォールバックする。
- **手の大きさ**：手首から4指のMCPまでの距離4本と、手のひら幅 `5 ↔ 17` の1.25倍の中央値。3D画像座標なら傾きによる見かけの縮みも補える。1.25は手のひら長への換算の初期値であり、実測による校正値ではない。ドラッグ感度の補正は従来どおりつかみ開始時に固定する。

開閉閾値0.32／0.55、安定待ち、追跡復帰のリセットは維持した。複数長の基準に合わせた実カメラでの閾値調整は未実施。

### 個別比較と判定値

`HandGestures.handFrame(result, width, height, options)` の第4引数で各補強を無効化できる。通常のカメラ処理はすべて有効。

```js
const current = HandGestures.handFrame(result, width, height);
const withoutAngles = HandGestures.handFrame(result, width, height, { jointAngles: false });
const withoutDepth = HandGestures.handFrame(result, width, height, { depthPinch: false });
const withoutMedian = HandGestures.handFrame(result, width, height, { stableHandSize: false });
const previous = HandGestures.handFrame(result, width, height, {
  jointAngles: false, depthPinch: false, stableHandSize: false,
});
```

片手フレームの `measurements` は `ratio2D`・`ratio3D`・`palmSize`（画像ピクセル単位）・`space`（`world`／`image3D`／`image2D`）と、各指の `pipBend`・`dipBend`・`extended`・`folded` を返す。角度が計算できない場合は `null`。両手で人差し指ポーズを認識した場合は `toggleHand.measurements` でも確認できる。この時点では番号付き骨格の画面表示は未追加。

## 2026年10月24日：優先度「中」の実装

優先度「中」の2件を実装。更新番号 `20261024-hand-debug-2`。優先度「低」の名前付き定数化は未着手。

- **親指下向き**：CMC `1` → MCP `2` → IP `3` → TIP `4` のMCP／IP曲げ角度がそれぞれ40度以下で、CMCからTIPの距離が手の基準長の0.5倍を超えることを伸展条件にした。角度算出不能なら伸展は確定しない。伸展は既存のworld／画像3D／画像2Dの選択に従い、画面下向きは従来のXY条件で別に評価する。4指の屈曲・親指の伸展・画面下向きがそろった場合だけ `thumbDown` とする。600ms保持と削除確認の流れは維持。
- **番号付き骨格**：カメラパネルの「骨格・判定値を表示」で有効化する。21点の番号と21本の接続線を手ごとに別色で表示し、ポーズ、ピンチ比率（採用値・XY・3D）、座標系、手の基準長、親指MCP／IP角度、伸展／下向き条件を確認できる。両手時もそれぞれの値を表示する。画像の左右反転と `object-fit: cover` の中央切り抜きを描画座標に反映し、番号自体は反転させない。

通常時はデバッグ描画と追加の手ごとの計算を行わない。表示中はプレビューを拡大し、小さい画面ではパネル内をスクロールできる。追跡タイムアウト・未検出・停止・カメラ切り替え時は古い骨格と判定値を消去する。映像・ランドマークの保存処理は追加していない。

### 個別比較

```js
const current = HandGestures.handFrame(result, width, height);
const withoutThumbExtension = HandGestures.handFrame(result, width, height, { thumbExtension: false });
```

`measurements.thumb` に `mcpBend`・`ipBend`（度、算出不能は `null`）、`extended`・`pointsDown` を追加。`thumbExtension: false` は従来の親指下向き条件だけで比較するためのオプションで、通常のカメラ処理では補強が有効。
