# カメラジェスチャーの実装・検証記録

2026年10月22日。実装計画A2、設計書7節に対応する。既存の静的UIプロトタイプへ接続した段階であり、P0のReact/Viteへの移行やA2の実機合格を意味しない。

## 起動

Macのターミナルから次の一つのコマンドで、初回の資産取得、ローカルサーバー起動、既定ブラウザの表示まで実行できる。

```sh
python3 scripts/try-gestures.command
```

「手で操作」を押してカメラを許可し、指を開いた片手を映す。手全体を右・左下などへ動かすと、その方向のノードへ選択が移る。止めると選択を保つ。アクティブなノードをつまんで手全体を動かし、指を開くと移動を確定する。開いた手では方向選択へ戻る。終了時はターミナルでControl+Cを押す。8000番ポートが使用中の場合は別の空きポートを選び、URLを表示する。

個別に実行する場合：

```sh
python3 scripts/setup-gesture-assets.py
python3 -m http.server 8000 --directory ui-prototype
```

Macでは `http://localhost:8000` を開き「手で操作」を押す。開いた指を100ms以上映すと、現在の選択ノードから方向選択を始める。選択がなければ中心ノードを起点にする。映像は鏡像で表示する。カメラは開始操作時に限って要求し、音声トラックは要求しない。

モデル取得スクリプトはMediaPipe Tasks Vision **0.10.32** とHand Landmarkerモデル **float16/1** を固定URLから取得する。SIMD／非SIMDのWASMを含めて同一配布元の `ui-prototype/mediapipe/` からロードする。配布時もこの生成ディレクトリを含めること。成功時には取得URL・サイズ・SHA-256を `manifest.json` に記録する。外部配布元への接続は取得時のみ必要で、ブラウザによる実行時の資産ロードはすべて同一配布元へ向ける。

このバージョンのパッケージはCJSとESMを提供する。WorkerではCJSを `vision_bundle.js` の名前で配布し、`exports/module.exports` のアダプターで読み込む。通常のESM Workerではなくclassic Workerとするのは、WASM初期化の `importScripts` に合わせるため。比較用のメインスレッド構成ではESMを使う。APIの確認元は[Google公式ガイド](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/web_js)。

iPadではlocalhost以外のHTTP URLではカメラを使えない。生成資産を含むディレクトリをHTTPSで配布して確認する。HTTPS配布先の設定は未実施。

## 旧方式の実装範囲（10月23日の方向切替より前）

以下はポインタ・ピンチドラッグ方式の記録。現行の操作仕様・検証は末尾を参照。

- 手のひらの平均座標による相対移動、左右反転、時間に応じた平滑化、3 CSS pxの不感帯、マップ領域での制限、初回のみの中央配置。
- 手の大きさで正規化したピンチ距離、開閉の別閾値、安定時間。開閉の閾値を超えた判定中は移動を止め、指先の曲げ伸ばしは移動座標に使わない。
- ピンチ開始時の対象固定、空白で閉じたままの対象取得の抑止、子孫を含む移動と一回のUndo。ズームを考慮し、親子関係は変えない。
- 追跡消失で停止し、300ms以内・同じ左右分類・十分な分類確信度・近い手首・ピンチ継続のときだけ基準を取り直して再開する。それ以外は取消して開指を待つ。左右分類と手首の近さは簡易判定であり、同じ側の別人の手を厳密に識別できるものではない。
- 通常のポインタ入力・編集中は手の操作を抑止。Esc、Undo、停止、画面の非表示、フォーカス離脱、ページ離脱で未確定移動を取り消す。画面復帰後の自動再開はしない。
- 開始・停止、権限拒否、機器不在、推論初期化／実行失敗、タイムアウトと再試行。再試行は「手で操作」をもう一度押す。
- 専用WorkerへのImageBitmap転送。処理中フレームは一つで、撮影フレームの重複や待ち行列は作らない。停止中に生成が終わったBitmapも解放する。Workerは各処理のfinallyで画像を閉じ、停止後に終了する。
- 保留中の自動保存で未確定のカメラ移動を保存しない。

## 計測と比較

「検証」を開くと最新フレームの推論時間と「フレーム取得→表示」の時間を別々に表示する。後者はBitmap生成開始から、結果反映後の次のrequestAnimationFrameまでの代理値。カメラの露光・撮影・実画面の描画完了は測れないため、手の動きから見た体感遅延とは区別する。

Workerが成立しない場合は「低頻度で試す（5fps）」で明示的に比較できる。自動フォールバックはしない。メインスレッドの推論が120msを3回続けて超えたら停止する。この値は初期の保護設定であり、快適さの合格基準ではない。入力の引っかかりや操作の停止があれば、その端末の手操作を保留する。
