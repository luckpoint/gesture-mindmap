# アイコンパレット設計

2026年10月24日。設計案。アプリの実装・素材の取り込みは未実施。

## 1. 要件と前提

- 「人のアイコン72種_分割」「日常生活アイコン72種ポスター_分割」の計144枚を使う。
- メニューから表示／非表示を切り替える。開く方向はPC・iPad・iPhoneとも右から。
- 「iPad/iPadは縦型の場合は非対応」は、文脈から **iPad／iPhoneの縦向きではパレットを提供しない** と解釈する。この場合、パレット本体とメニュー項目を両方非表示にする。マップ編集は引き続き利用できる。
- ノードへの配置操作は未指定のため、以下では「アイコンを選び、子として追加／選択ノードに適用」を提案する。

## 2. 確認した現状

| 対象 | 現状 |
|---|---|
| 人物素材 | 72枚、すべて128×112px、合計1,546,611 bytes |
| 日常生活素材 | 72枚、すべて128×112px、合計1,014,668 bytes |
| 素材の背景 | 分割手順では白いキャンバスに配置。白背景を含む元PNGをそのまま使用する |
| 既存メニュー | 右上の「ファイル」にJSON書き出し／読み込みがある |
| 画像操作 | `attachNodeImage()` が子ノード追加と既存ノードへの適用に対応 |
| 保存 | 画像をOPFS、マップと履歴をRxDBに保存。画像込みJSONに対応 |
| 画像表示 | 既存の画像カードは192×144px。選択／編集中にノード文字を重ねて表示 |
| レイアウト | `--side` があり、キャンバスやツール類の右側余白に利用できる。現時点は0px |

根拠：`ui-prototype/index.html`、`images/{store,format,upload}.js`、[ノード画像設計](node-images-design.md)、[複数マップ保存設計](multi-map-storage-design.md)、[素材の分割記録](../guides/icon-sheet-splitting.md)。寸法・枚数・容量は指定フォルダ内のPNG全144枚を確認した値。

## 3. メニューと開閉

既存の「ファイル」を「メニュー」に変更し、次の項目を追加する。メニューをもう一つ新設する必要はない。

```text
メニュー
  アイコンパレットを表示   ← 開いているときは「アイコンパレットを隠す」
  ────────────────
  書き出す（JSON）
  読み込む
```

- 初回起動・ページ再読み込み時は閉じた状態。開閉状態は永続保存しない。
- メニュー項目を押すとメニューが閉じ、右端からパレットが現れる。
- 閉じる方法は、パレット右上の「×」、メニュー項目の再操作、パレット内でのEscape。
- キャンバスを押しても閉じない。ノードを選び直しながら使える常設の補助領域とする。
- 閉じる際は、パレット内にフォーカスがあればメニューボタンへ戻す。
- 開閉は表示だけの変更なのでUndo履歴に入れない。マップを切り替えても開閉状態は維持し、アイコンの選択は解除する。

## 4. パレットの構成と配置操作

```text
┌────────────────────────────┐
│ アイコンパレット        × │
│ [人物 72] [日常生活 72]    │
│ [アイコン名で検索       ] │
├────────────────────────────┤
│ [画像] [画像] [画像] …    │
│  名前   名前   名前       │
│           ↕ スクロール    │
├────────────────────────────┤
│ 家 →「週末の予定」        │
│ [子として追加] [画像にする]│
└────────────────────────────┘
```

- カテゴリは「人物」「日常生活」の2つ。初期表示は人物。選択中カテゴリを見た目と読み上げで示す。
- 各カテゴリ内は元ファイルの連番順。人物の年代別など追加の分類UIは初期版では設けない。
- アイコンは画像と短い名前を表示。連番は表示名に含めない。同名の種類は末尾の番号を残して区別する。
- 検索は選択中カテゴリの名前に対する部分一致。日本語・英語の名前で検索できる。Unicode正規化を行い、結合文字による濁点の違いを吸収する。0件なら説明を表示する。
- 一覧内のクリック／タップはアイコンの選択だけを行う。フッターにアイコン名と対象ノード名、二つの操作ボタンを出す。
- **子として追加**：選択ノードの子に画像カードを一つ作る。選択ノードがない場合は中心ノードを親とする。新規ノードの文字はアイコン名とする。
- **画像にする**：選択ノードの文字・親子関係を保ち、画像を適用する。既に画像がある場合の文言は「画像を置き換える」。中心ノードも対象。
- 対象ノードがない場合は「画像にする」を無効化する。フッターには「中心ノードの子に追加」と明示する。
- どちらも適用は明示的なボタン操作で一回だけ行い、Undo一回で戻せる。画像の取り外しは既存のノードメニューを使う。
- 追加後もパレットは開いたまま。子を追加した場合は新しい子を選択するため、フッターの対象名も即座に更新する。画像の選択は維持する。
- PC／タッチとも同じ操作で利用する。パレットからのドラッグ＆ドロップ・キャンバス空白への直接配置は後続とする。

## 5. 右側レイアウトと端末対応

| 環境 | 表示条件 | パレット幅の初期案 | 一覧 |
|---|---|---|---|
| PC | 縦横とも利用可 | 320px。狭いウィンドウでは240pxまで縮小 | 通常4列、狭い場合3列 |
| iPad | 横向きのみ | 320px | 4列 |
| iPhone | 横向きのみ | 240px | 3列 |
| iPad／iPhoneの縦向き | 提供しない | 0px | メニュー項目も非表示 |

- パレットは画面右端に固定し、上端から下端まで使う。白系の面、左境界線、既存のコーラル色・角丸・フォントを使う。
- 開くと `--side` をパレット幅にする。キャンバスと操作UIは残りの左側に収め、パレットがノードやズームボタンを覆わない構成とする。
- ヘッダーとフッターは固定し、アイコン一覧だけ縦スクロールする。スクロールをキャンバスのパンへ伝えない。
- セル画像は約56×49px、セルの幅・操作領域は64px以上を目安とする。ボタンは既存の48pxタッチ寸法に合わせる。長い名前は省略し、選択時にフッターで全文を確認できる。
- ノード画像は既存の192×144px枠を使い、元画像の縦横比を保つ。アイコン専用のノード形式は作らない。
- スライドは既存の約220msの設定に合わせる。動きを減らす設定では即時切替にする。
- 開閉時に倍率とノード座標は変えない。選択ノードが隠れる場合だけ、パンして残りのキャンバスへ収める。
- キャンバスの実寸を基準に、中央配置・全体表示・選択ノードの可視化・ノードメニューの幅と位置・手操作の境界を計算する。
- **既存の画面幅基準のCSSをそのまま流用しない。** パレットを除いたキャンバス幅に応じて、トップバーを折り返し、ドックをコンパクト表示する。指示欄・通知・開発パネルも左側に収める。高さの小さい横向き端末では全体表示の計算に負の有効高さを渡さない。
- iPhone／iPadのセーフエリアを、パレットの上下・右端およびキャンバス側の左端に反映する。

### 回転時

- iPad／iPhoneを縦にすると、開いていたパレットを閉じ、幅予約を0に戻す。メニュー項目も隠す。
- 横に戻しても自動では開かない。メニューから再び開く。カテゴリと検索語はページ内で保持する。
- 縦に回転した際、パレット内にフォーカスがあればメニューボタンへ戻す。マップと適用済み画像は維持する。
- 端末種別と向きは一か所で判定する。iPadのデスクトップ表示も受入対象。PCの単に縦長なウィンドウをiPad／iPhoneと判定しない。
- 向きは端末／画面の向きを基準にし、ソフトウェアキーボードで表示領域が横長になっただけでは縦端末を対応扱いにしない。確実に判別できないタッチ端末は縦向き非表示を保守的な代替とし、実機で調整する。

## 6. 素材と保存の構成

実装時に元PNGを変更せず、静的アセットとしてリポジトリへコピーする。全体で約2.44MiB。デスクトップの絶対パスをアプリから参照しない。

```text
ui-prototype/icons/
  people/01.png … 72.png
  daily/01.png  … 72.png
  catalog.js             ID・画像パス・表示名の辞書キー
  palette.js             一覧・検索・選択・開閉の制御
  palette.css            右パレットとレスポンシブ表示
```

- IDは `people-01`／`daily-01` のように安定したASCII文字列とする。日本語名は `i18n.js` の日英辞書で管理し、ラベル・検索・読み上げに使用する。
- パレットのサムネイルは静的PNGを直接表示。表示カテゴリの画像を遅延読み込みし、144枚すべてを起動時にデコードしない。
- 適用ボタンを押した時点で対象の静的PNGを取得し、既存の `imageStore.put()` → `attachNodeImage()` の処理を通す。元PNGは縮小・再圧縮しない。
- ノードには既存の `image: { assetId, alt, width, height }` だけを持たせる。カタログID・静的URLは保存データに追加しないため、スキーマの変更は不要。
- 同じアイコンの反復利用は既存のSHA-256による重複排除を利用する。未使用の144枚をOPFSへ一括登録しない。
- 画像込みJSONには使用中のアイコン本体も含める。別端末への移動後や、将来カタログを変更した後も復元できる。
- アイコンのaltは操作時の表示言語の名前。既存ノードの文字は変更しない。作成済みノードの文字・altは、以後の言語環境変更で自動翻訳しない。
- 静的配信に同梱し、Codex指示機能のON／OFFに依存させない。既存の画像保存が利用できる環境を前提とする。

## 7. 処理中・失敗・アクセシビリティ

- 適用開始時点の対象ノードID・マップセッション・revisionを固定し、画像取得と保存の後に再確認して一回commitする。待機中に選択ノードが変わった場合も適用を中止し、意図しないノードへ追加しない。
- 開閉・カテゴリ切替・回転・マップ切替で適用待機を無効化できる世代番号を持つ。PNG取得を中止できた場合は中止し、保存済みでも未適用なら既存の未参照画像として扱う。
- 処理中は両方の適用ボタンを無効化し、二重追加を防ぐ。通信・デコード・容量エラーではマップを変更せず、再試行可能な状態を残す。
- 閲覧専用のマップでもパレットの閲覧は可能。適用は無効化して理由を表示する。
- 編集中・ドラッグ中・つなぎ替え中・削除確認中・指示の適用確認中は適用不可。パレット操作時は手ジェスチャーを中断し、パレット内にフォーカスがある間は手操作で対象ノードを変更しない。
- パレットは名前付きの補助領域とし、モーダルにしない。開いたときは閉じるボタンへフォーカスを移す。Tabでキャンバスと行き来できる。
- アイコン選択はボタンと選択状態で表現する。選択枠を付け、色だけに依存しない。検索・カテゴリ・適用・閉じるには読み上げ名を付ける。
- パレット内のキー操作をマップのノード追加・削除・Undoなどへ流さない。Escapeは開いているメニュー／ダイアログの処理を優先し、その後パレットを閉じる。
- 一覧画像の取得失敗はそのセル内で示し、一覧全体を使用不能にしない。失敗した画像は適用不可とする。

## 8. 実装順と受入条件

1. 素材コピーとカタログ作成。各カテゴリ72件、ID・パス・日英名・寸法の対応を確認する。
2. メニュー項目・右パレット・カテゴリ・検索・アイコン選択を実装する。
3. 二つの適用操作を既存の画像保存処理につなぎ、競合とエラーを扱う。
4. キャンバス幅に応じたUI調整、iPad／iPhoneの向き制御、回転・フォーカス制御を実装する。
5. 既存テストに加え、操作・保存・回転を確認する。

| 確認 | 合格条件 |
|---|---|
| メニュー | 表示／非表示と「×」が同期し、右から開く。再読み込みでは閉じている |
| 素材 | 2カテゴリ各72件、順序と名前が一致。日本語の濁点を含む検索も一致する |
| ノード操作 | 子追加・既存画像の置換・中心への適用ができ、各操作をUndo／Redo一回で戻せる |
| 保存 | 再読み込み・マップ切替・画像込みJSONでの別環境への移動後も同じ画像が出る |
| 競合 | 画像取得中の選択変更・マップ切替・縦回転・編集権喪失で誤適用しない |
| 失敗 | PNG取得・保存失敗や二重タップで余分なノードや不完全な参照ができない |
| PC | 広い画面／狭いウィンドウ／縦長ウィンドウで利用できる |
| iPad | 横向きで右から開き、縦向きでメニュー項目とパレットが消える。デスクトップ表示も確認 |
| iPhone | 横向きで3列表示と適用が使え、縦向きで両方消える。小さい横画面とノッチも確認 |
| 回転とキーボード | 横→縦→横で自動再表示しない。キーボード表示だけで非対応端末に現れない |
| レイアウト | パレットに操作UIが重ならず、選択ノードとノードメニューを操作できる |
| 入力と読み上げ | マウス・タッチ・キーボードで選択／適用／閉じるができ、マップのキー操作と競合しない |
| 回帰 | 既存の画像アップロード、JSON読み込み／書き出し、画像取り外し、指示機能OFFが動作する |

自動テストはカタログの整合・適用／競合・保存の回帰に絞る。右からの開閉、実寸レイアウト、端末判定と回転はブラウザとiPad／iPhone実機で確認する。
